## 보여 드릴 것: AI 서버 코드 구조

```
폰 브라우저 (화면 코드, 키 없음)
   │  파일·입력만 보냄
   ▼
web/src/app/api/…/route.ts  (Vercel 서버에서만 실행)
   ├─ 입력 검사 (zod, 형식·길이·파일 4MB)
   ├─ 하루 사용 횟수 확인  ← web/src/lib/ai-limit.ts (서명한 쿠키)
   ├─ Claude 호출          ← web/src/lib/claude.ts의 getAnthropic() (키는 여기서만 읽음)
   └─ 결과 검사 후 돌려줌 (성공했을 때만 사용 1회 기록)
```

## 질문 (중요한 순서)

1. **AI 사용 횟수 제한을 어디에 저장하면 좋을까요?** 서버에 데이터를 저장하지 않으려고 '서명한 쿠키'로 셉니다. 쿠키를 지우면 횟수가 초기화되고, 마지막 안전장치는 콘솔 월 한도입니다. 시범 운영(20~30명) 규모에서 이걸로 충분한지, 횟수만 세는 작은 저장소(예: Vercel KV, IP 기준)를 써야 하는지.
2. **서버 코드 구조**가 괜찮은지: 입력 검사 → 횟수 확인 → Claude 호출 → 결과 검사 순서, 오류 처리, `maxDuration`(30~60초).
3. **개인정보**: 강의계획서에 교수님 연락처가 있는데 그대로 AI에 보내도 되는지, 브리핑에 일정 제목을 보내는 것, 저장소가 공개(Public)인 것.
4. **비용**: Haiku 5.5, 월 사용 한도 금액, 입력·답변 길이 상한이 적절한지. (강의계획서 1개 약 2원 수준)
5. **브라우저 저장**: 아이폰 7일 삭제 문제를 '홈 화면에 추가' 안내 + 내보내기·가져오기로 막는 게 충분한지.
6. **`.ics`**: 하루 종일 일정 + 전날 9시 알림, 구글 캘린더가 알림을 무시하는 문제.
7. **시간표**: KLAS 시간표 캡쳐(교수님 이름 포함)를 AI에 보내 읽는 방식이 괜찮은지. 처음 PRD에 없던 기능이라 기능 동결(11/16)까지 넣어도 되는지.

8. **범위 추가 (11/3 결정)**: 취업 준비(취준 일정·대외활동 목록·스펙 영수증 + 역량 공백 지도)와 계산 화면(오늘의 한 가지·기말 필요 점수·학기 리스크 지도)을 11/16까지 더하려 합니다 (`docs/PRD.md`). 새 AI API는 `/api/posting`, `/api/receipt` 2개이고, 계산 화면은 AI 없이 코드로 합니다. 2주 안에 무리인지, 무엇부터 빼면 좋을지.

## 알려진 한계 (먼저 말씀드릴 것)

- 하루 20회 제한은 쿠키 기반이라 우회 가능 (1번 질문)
