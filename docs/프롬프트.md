# Claude Code 프롬프트 — 디자인 적용 (v5)

디자인 캔버스 '우니스 앱 디자인 시안'의 **최종 조합 → v5**(홈 · 캘린더)를 코드로 옮기는 프롬프트입니다. 2026-11-03 정리.

## 진행 순서 (프롬프트마다 반복)

1. `git switch main` → `git pull` → 프롬프트에 적힌 브랜치 만들기 (`git switch -c feature/...`)
2. Claude Code 권한 모드를 **계획**으로 두고 프롬프트를 통째로 붙여 넣기. 캔버스 v5 화면 캡처를 같이 붙이면 더 비슷하게 나옵니다
3. 계획을 읽고 괜찮으면 **수동**으로 바꿔 진행
4. 폰에서 확인 → 커밋 → push → PR → 팀원이 Merge
5. 다음 프롬프트로

| 순서 | 프롬프트 | 브랜치 |
|---|---|---|
| 1 | 디자인 규칙 + 공통 부품 | `feature/design-system` |
| 2 | 홈(오늘의 브리핑) | `feature/home` |
| 3 | 강의계획서 → 캘린더 확인 화면 | `feature/calendar` |
| 4 (B) | 메일·시험 대비 화면 + 백업 카드 새 디자인 | `feature/mail-exam-design` |

1·2는 끝났어요 (#21 디자인 기초, #26 홈. 홈과 함께 시간표 캡쳐 #25, 모든 화면의 새 탭바도 들어감). 3은 A, 4는 B가 합니다.

## 프롬프트 1 · 디자인 규칙 + 공통 부품

```
우니스 화면 디자인을 정했어. 기능을 만들기 전에 디자인 기초부터 깔자. 먼저 계획만 보여 줘.

1) docs/DESIGN.md를 만들고 아래 규칙을 정리해 줘. CLAUDE.md '디자인' 항목에 "모든 화면은 docs/DESIGN.md를 따른다" 한 줄 추가.

[색]
- 바탕 #F2F1F4, 블록 #FFFFFF, 블록 안 구분선 #F0EEF2, 바깥 테두리 #EAE7EC(탭바·입력칸에만)
- 글자 #1C1A1E, 보조 글자 #6B6570
- 포인트(버건디) #8C1D40, 옅은 포인트 #F8EEF1, 진한 포인트 #6E1632
- 일정 종류: 과제 #2756A6/#E4EBF8, 퀴즈 #22553A/#E3F1E7(점 #2F7A4C), 시험 = 포인트색/#F8EEF1, 확인 필요 #7A4300/#FFF6E8(테두리 #F2C98A, 점 #C77A00)
- 포인트색으로 꽉 채운 블록은 화면당 하나. 나머지 포인트색은 오늘 날짜, 현재 시각 선, D-day 숫자, 주요 버튼에만
[글꼴]
- 본문 IBM Plex Sans KR(400/500/600/700), 숫자·시간·날짜·D-day는 IBM Plex Mono(500/600). next/font/google로 불러오기
- 크기: 화면 제목 22px/700, 섹션 제목 15px/700, 본문 14~15px, 보조 12px, 작은 라벨 11px
[모양]
- 블록형: 회색 바탕 위에 흰 블록. 블록은 테두리·그림자 없이 모서리 18~20px, 블록 사이 8~10px
- 블록 안은 가는 구분선(#F0EEF2)으로만 나눈다. 블록 안 강조 블록은 하나만(AI 추천)
- 좌우 여백 16px, 블록 안쪽 여백 12~14px
- 같은 정보·바로가기를 두 곳에 두지 않는다. 기능 이동은 하단 탭바에서
- 버튼 모서리 10~14px, 누를 수 있는 것은 최소 44px, 아이콘 lucide-react(선 1.8)
[레이아웃]
- 폰(폭 375~430px) 기준, PC에서는 가운데 최대 폭 480px
- 하단 탭바(흰색, 위쪽 얇은 테두리) 5칸: 홈 · 일정 · (가운데 48px 둥근 포인트색 + 버튼: 계획서·캡쳐 올리기) · 시험 대비 · 메일

2) Tailwind CSS 4의 @theme(globals.css)에 위 색·글꼴·모서리를 이름 붙여 등록(--color-brand, --color-surface, --color-muted 등)

3) web/src/components/ui에 모양만 있는 공통 부품(기능 로직 없이):
- AppShell(바탕·최대 폭·탭바), BottomTabBar(현재 탭 표시, 가운데 + 버튼)
- Block(흰 블록), Button(primary/secondary/ghost), Badge(일정 종류별 색)
- CheckRow(왼쪽 시각 또는 체크박스 + 제목/보조 글 + 오른쪽 배지·버튼 자리)
- WeekStrip(월~일, 오늘은 포인트색 원, 일정 있는 날 아래 점)
- SegmentedTabs(목록|달력), BottomSheet(아래에서 올라오는 창, 뒤 배경 어둡게, 손잡이)

4) web/src/app/page.tsx의 PAUSEPAY 문구는 아직 두고, /design 경로에 부품을 모아 보여 주는 확인용 페이지를 만들어 줘.

끝나면 폰에서 /design을 열어 확인하는 방법을 알려 줘.
```

## 프롬프트 2 · 홈(오늘의 브리핑)

```
docs/DESIGN.md와 docs/PRD.md의 '핵심 2. 오늘의 브리핑'을 읽고 홈(web/src/app/page.tsx)을 만들어 줘. 먼저 계획만 보여 줘.
PAUSEPAY 홈 문구를 지워도 되는지 계획에 표시해 줘. 이번 단계는 AI 없이 가짜 데이터로 화면과 동작만.

[데이터]
- web/src/lib/events.ts: 일정 타입 + localStorage 저장·불러오기(키 "unis.events")
  Event = { id, course, title, date(YYYY-MM-DD), time?(HH:mm), endTime?, type: 'class'|'assignment'|'quiz'|'exam'|'activity', source: 'syllabus'|'manual', needsReview?: boolean, rawText?: string, done?: boolean }
- 저장된 게 없으면 예시 일정을 보여 주고 '예시 데이터'라고 작게 표시

[화면, 회색 바탕 위 흰 블록. 위에서 아래로]
1. 머리(블록 아님): 작은 글씨 '오늘' + 날짜 제목(11월 3일 화요일), 오른쪽 흰 원형 프로필·설정 버튼
2. 요약 블록 3개 한 줄(모서리 18px, 높이 약 92px):
   - 다음 수업: 포인트색으로 꽉 채움, 흰 글자. 라벨 / 과목(17px 굵게) / "15:00 · 3h 후"(Mono)
   - 이번 주 마감: 흰 블록. 라벨 / 가장 급한 D-n(Mono 19px, 포인트색) / "○○ 외 N건"
   - 기말고사: 흰 블록. 라벨 / D-n(Mono 19px) / "시험 대비 →"(포인트색)
   - 각 블록은 누르면 해당 화면으로. 메일 같은 기능 바로가기는 넣지 않는다
3. 큰 흰 블록 하나(모서리 20px, 남은 높이를 채움) 안에:
   - 맨 위 이번 주 요일 줄(WeekStrip). 누르면 아래 목록이 그날로 바뀜. 아래 구분선
   - '오늘 일정' 제목 + 오른쪽 작은 글씨("4개 중 1개 지남")
   - 타임라인(CheckRow): 왼쪽 시각(Mono), 오른쪽 제목/보조 글, 줄 사이 가는 구분선
   - 지나간 일정은 취소선과 흐린 글자. 현재 시각에 포인트색 가는 선 + 시각
   - 과제·퀴즈·대외활동은 오른쪽 체크박스로 완료(localStorage 저장)
   - 현재 시각 선 바로 아래에 빈 시간 추천: 다음 일정까지 30분 이상 비면 옅은 포인트 블록(#F8EEF1, 모서리 16px)
     · "빈 시간 N시간 M분 · 이거 하기 좋아요", 마감 가장 가까운 미완료 과제, D-day
     · 버튼 '다른 일'(흰색, 다음 후보) / '시작'(포인트색)
     · 추천은 지금은 규칙(마감 가까운 순), AI 한 줄 추천은 나중에 붙일 수 있게 함수 하나로 분리
4. 하단 탭바(AppShell)

끝나면 확인: 폰에서 요일 바꾸기, 체크 후 새로고침해도 유지, 빈 시간 블록이 시간에 따라 나타나는지.
```

## 프롬프트 3 · 강의계획서 → 캘린더 확인 화면

```
docs/DESIGN.md와 docs/PRD.md의 '핵심 1. 강의계획서 → 캘린더'를 읽고 web/src/app/calendar에 '찾은 일정 확인' 화면을 만들어 줘. 먼저 계획만 보여 줘.
이번 단계는 AI 없이, 찾았다고 치는 가짜 일정 7개(그중 1개 needsReview: true, rawText: "11월 둘째 주 조별 발표")로. 일정 타입과 저장은 web/src/lib/events.ts를 쓴다.

[화면, 회색 바탕 위 흰 블록. 위에서 아래로]
1. 머리(블록 아님): 뒤로 버튼, 제목 "찾은 일정 N개", 아래 작은 글씨 파일 이름, 오른쪽 SegmentedTabs(목록 | 달력)
2. 달력 블록(모서리 20px):
   - 위쪽 "2026년 11월" + 이전·다음 달 버튼, 요일 줄(일~토), 날짜(Mono)
   - 오늘은 포인트색 테두리 원, 일정 있는 날은 숫자 아래 종류별 색 점, 확인 필요는 주황 점
   - 블록 아래쪽에 구분선 + 색 설명(퀴즈·과제·시험·확인 필요)
   - 날짜를 누르면 아래 체크리스트가 그날로 스크롤
3. 체크리스트 블록 "캘린더에 넣을 일정" + 오른쪽 '모두' 체크:
   - 확인 필요 일정은 맨 위 고정: 옅은 주황 띠(#FFF6E8, 위아래 #F2C98A 선), 체크박스, 제목, 원문 문구, 포인트색 '날짜 고르기' 버튼
   - 이번 달 일정은 CheckRow(체크박스, 날짜 Mono, 제목, 종류 Badge)
   - 다른 달은 접힌 줄 "9·10월 · 퀴즈·보고서·중간고사 3/3"(오른쪽 ∨), 누르면 펼침
4. '날짜 고르기' → BottomSheet:
   - 확인 필요 배지, 제목, "계획서 원문: ○○"
   - 날짜 후보 3개를 큰 버튼으로(그 주 수업 요일 우선, 아래 작은 글씨로 요일) — 고른 것은 포인트색
   - '하루 전 알림 받기' 체크, 버튼 '빼기'(회색) / '○○로 저장'(포인트색)
5. 맨 아래 흰 바(위쪽 얇은 테두리): 주요 버튼 "N개 일정 캘린더에 추가"(체크된 개수), 아래 작은 안내 ".ics 파일로 받아요 · 하루 전 알림 포함"
   - 확인 필요가 남아 있으면 추가 버튼을 누를 때 그 일정의 날짜 고르기 창을 먼저 연다
6. 목록 보기: 달력 블록 없이 체크리스트 블록만

.ics는 ics 패키지로(설치 전에 이유 설명). 계획서·KLAS 캡쳐 올리기는 하단 탭바 가운데 + 버튼에서 이 화면으로 들어오는 흐름으로 연결해 줘(올리기 화면 자체와 AI 연결은 다음 단계).
끝나면 확인: 폰에서 날짜 고르기 창, 체크 개수에 따라 버튼 숫자 변화, 내려받은 .ics가 구글·아이폰 캘린더에 들어가는지.
```

## 프롬프트 4 · 메일·시험 대비 화면 + 백업 카드 새 디자인 (B)

```
docs/DESIGN.md를 읽고, 교수님 메일(web/src/app/mail/page.tsx)과 시험 대비(web/src/app/exam/page.tsx) 화면,
홈 설정 창 안의 내보내기·가져오기 카드(web/src/app/data-backup.tsx)를 새 디자인으로 바꿔 줘. 먼저 계획만 보여 줘.
이번 단계는 모양만 바꾸고, 기능(AI 호출·스트리밍·채점·저장·하루 사용 제한)은 그대로 둬.

[지킬 것]
- 공통 부품 web/src/components/ui(AppShell, Block, Button, Badge, CheckRow, SegmentedTabs, BottomSheet)를 가져다 써.
  부품 파일 자체는 A 담당이라 고치지 마. 부품에 없는 모양이 필요하면 화면 파일 안에서 만들고, 계획에 적어 줘
- 색은 globals.css의 이름(bg-canvas, bg-surface, text-ink, text-muted, bg-brand, bg-brand-soft, border-line 등)만 쓰고,
  옛 이름(accent, accent-soft, foreground, background)과 rounded-2xl·테두리 카드는 없애
- 화면 틀: AppShell(회색 바탕, 최대 폭 480px, 좌우 16px) 안에
  머리(블록 아님): 작은 회색 라벨 + 화면 제목 22px 굵게 + 한 줄 설명
  그 아래 흰 블록들(모서리 20px, 테두리·그림자 없음, 블록 사이 8~10px). 블록 안은 가는 구분선(divider)으로만 나눔
- 포인트색으로 꽉 채운 것은 화면당 하나(주요 버튼). 강조 블록(옅은 포인트 bg-brand-soft)도 블록 안에 하나만
- 입력칸: 흰 바탕 + 얇은 테두리(border-line), 모서리 12px, 높이 44px 이상. 누를 수 있는 것은 모두 44px 이상
- 숫자·점수·쪽 번호·D-day는 font-mono
- 오류 안내는 '확인 필요' 색(bg-review-soft, text-review, border-review-line)
- 아이콘은 lucide-react(선 1.8). 하단 탭바는 layout.tsx가 이미 그리니 화면에 따로 넣지 마

[화면별]
- 메일: 상황 고르기는 SegmentedTabs나 칩 버튼, 과목·하고 싶은 말 입력, '초안 만들기'(주요 버튼),
  스트리밍되는 초안은 흰 블록 안에, 복사 버튼은 secondary
- 시험 대비: 자료 올리기·쪽 범위 → 요약 5줄·어려운 말(블록) → 10문제(문제마다 구분선), 채점 결과 점수는 Mono 큰 숫자,
  틀린 문제 다시 풀기. 정답·오답 표시는 퀴즈 색(quiz)·포인트색으로
- 백업 카드: 설정 창(BottomSheet) 안에 들어가므로 바깥 테두리 카드 없이, 제목 15px 굵게 + 설명 + 버튼 두 개(secondary)

끝나면 확인: 폰(375px)에서 두 화면을 처음부터 끝까지 한 번씩 써 보고(메일 초안 1개, 퀴즈 1번 채점),
가로로 넘치는 곳이 없는지, 홈 설정 창의 백업 카드 모양. next build·ESLint 통과.
```
