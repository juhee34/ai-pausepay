# 우니스 PRD (기능 명세)

2026-11-03 기준 (같은 날 개정: **취업 준비** 기능과 시안 '학점을 위한 의사결정' 추가). 기능 범위나 일정이 바뀌면 이 문서를 먼저 고칩니다.

## 한 줄 소개
대학생을 위한 AI 비서. 수업 일정과 취업 준비를 한곳에서 챙기고, 오늘 할 일·기말 필요 점수·위험한 주를 숫자로 알려 주며, 끝난 활동은 스펙 영수증으로 남깁니다.

**이름의 뜻**: UNIS = **UNIfied Student**. UNI는 '하나'(unify), S는 학생(Student). "흩어진 대학 생활을 하나로 잇는 학생 비서"라는 뜻입니다.

## 풀려는 문제
- **마감이 두 군데에 있다**: 과제·시험은 KLAS에, 대외활동·자격증·공고 마감은 여기저기에.
- **시간을 어디에 쓸지 모른다**: 무엇이 학점에 중요한지, 기말을 몇 점 받아야 하는지 계산해 본 적이 없다.
- **한 일이 남지 않는다**: 활동은 했는데 자소서를 쓸 때 기억나지 않는다.

## 누구를 위한가 (가상 페르소나)
- **지원** — 경영학부 2학년. "과제가 한 주에 몰리면 뭐부터 해야 할지 모르겠어요. 기말을 몇 점 받아야 B+인지도 모르고요"
- **민재** — 4학년, 서포터즈·공모전 + 하반기 공채 준비. "수업 마감이랑 지원 마감이 다 따로 있어요. 활동은 많이 했는데 자소서 쓸 때 기억이 안 나요"

## 발표 데모 흐름 (1분 30초)
강의계획서 올리기 → 캘린더 → 오늘의 한 가지 → 기말 필요 점수 → 학기 리스크 지도 → 공고 캡쳐 → 스펙 영수증 → 역량 공백 지도.

이미 배포: ①(평가 비율 제외) ②(오늘의 한 가지 제외) ③ ④ ⑤(타이머). 나머지는 11/20까지.

**들어가는 곳**: 탭바는 홈 · 우선순위 · ＋ · 취업 · 마이페이지(`/my`)입니다. 일정은 홈에 합쳤습니다: 큰 달력과 고른 날의 일정, 저장된 일정 목록이 홈에 있고, 오른쪽 위 메뉴(막대 3개) 안의 '강의계획서 넣기'가 올리기 화면(`/calendar`)을 엽니다. 시간표 바꾸기와 내보내기·가져오기도 이 메뉴에 있습니다. 가운데 ＋를 누르면 **전체 기능** 창이 올라와 여러 기능이 묶음별 타일로 보입니다 — 학교(기말 필요 점수·학기 리스크 지도·시험 대비·교수님 메일·집중 모드), 취업 준비(공고·자격증 올리기·스펙 영수증·역량 공백 지도), 내 정보(시간표 캡쳐). 자세한 모양은 `docs/DESIGN.md`. 오늘의 한 가지는 탭바의 '우선순위'와 홈 추천 블록으로 열립니다. 집중 모드는 오늘의 한 가지의 '집중 시작'과 전체 기능 창으로, 스펙 영수증·역량 공백 지도는 '취업' 탭(대외활동 화면)의 버튼으로도 들어갑니다.

## 계정 (11/4 멘토 검토 반영)

로그인은 **선택**입니다. 로그인하지 않아도 모든 기능을 지금처럼 쓰고, 데이터는 그 폰 브라우저에만 남습니다.

| 기능 | 무엇을 | 끝났다는 기준 |
|---|---|---|
| ⑪ Google 로그인 | Firebase Authentication의 Google 로그인. 이름·이메일만 받음 (캘린더 권한 X → 구글 심사 불필요). 마이페이지(`/my`)에서 로그인·로그아웃 | 두 폰(아이폰 사파리·안드로이드 크롬)에서 로그인·로그아웃이 된다. 로그인 안 해도 다른 화면이 그대로 동작한다 |
| ⑪ ICS 구독 주소 | 로그인 사용자에게 본인만 아는 긴 주소를 주고, 캘린더 앱이 '구독'해 우니스 일정을 주기적으로 가져감. 주소 다시 만들기 버튼 | 구글·아이폰 캘린더에서 구독하고, 우니스에 일정을 추가하면 캘린더에도 나타난다 (구글은 반영이 몇 시간 걸릴 수 있음) |
| ⑫ AI 사용량 마이페이지 | 로그인 사용자별 기능별 AI 사용 횟수(오늘·이번 주), 하루 제한까지 남은 횟수. 횟수는 서버 코드가 Firestore에 기록 | 로그인하고 AI 기능을 쓰면 마이페이지 숫자가 늘어난다. 다른 폰에서 같은 계정으로 보면 숫자가 같다 |
| ⑬ 계정 백업 | 로그인 사용자의 정리된 데이터(시간표·일정·대외활동 등)를 본인 계정에 올리고 다른 폰에서 받기. 원본 파일·이미지는 저장 안 함 | 아이폰에서 백업 → 안드로이드에서 같은 계정으로 받으면 같은 일정이 보인다 |
| ⑭ 시범 기간 익명 통계 **(3순위, 미룸)** | 기능 이름·날짜·횟수만 기록 (쓴 내용 X). 통계로 꺼낼 때 이름·이메일 제외. `STATS_COLLECTION=off`면 기록 안 함 | 끄기 설정이 동작하고, 꺼낸 통계 파일에 이름·이메일이 없다 |

- **하루 AI 사용 제한**: 로그인 사용자는 계정별(Firestore, 쿠키를 지워도 유지), 로그인 안 한 사용자는 지금처럼 기기 쿠키별.
- **Firestore 접근 규칙**: 사용자 문서는 본인(uid)만 읽고 쓰기. 사용량·통계는 서버 코드만 쓰기.
- **동의서·안내문**: 로그인은 선택, 시범 기간 익명 통계 수집과 끄는 날짜, 계정 백업 시 저장되는 것과 저장되지 않는 것, ICS 구독 주소는 남에게 알려 주지 말 것.

## 핵심 1. 강의계획서 → 캘린더 (대표 기능)
- **누가·언제**: 개강 첫 주, 수강 과목의 강의계획서를 받았을 때
- **무엇을**: 강의계획서 PDF나 **KLAS 화면 캡쳐(이미지)**를 올리면 AI가 과제·퀴즈·중간·기말 날짜를 뽑아, 확인 후 캘린더 파일(.ics)로 내려받는다.
- **흐름**
  1. PDF 또는 캡쳐 이미지(PNG·JPG) 선택 → 올리기 전 크기 확인 (4MB 넘으면 안내)
  2. `web/src/app/api/syllabus`에서 Claude API가 `{과목, 제목, 날짜, 종류(과제/퀴즈/중간/기말/기타)}` 목록(JSON)을 돌려줌 → `zod`로 형식 검사
  3. 날짜 확인·수정 화면 (사용자가 고친 뒤에 저장)
  4. `localStorage`에 저장 + `.ics` 내려받기 (알림 포함) → 구글·애플 캘린더에 추가
- **추가 (11/4~): 성적 평가 비율 읽기**
  - 같은 호출에서 `grading: [{항목: "중간"|"기말"|"과제"|"퀴즈"|"출석"|"기타", 비율(%)}]`도 함께 받는다. 계획서에 없으면 빈 목록 (지어내지 않음)
  - 확인 화면 아래에 '평가 비율' 줄(예: 중간 30 · 기말 30 · 과제 20 · 퀴즈 10 · 출석 10)을 보여 주고, 합이 100이 아니면 '확인 필요'
  - 저장: `localStorage` 키 `unis.grading.v1` = `{ [과목]: [{name, weight}] }`. ⑥ 기말 필요 점수와 2-1 오늘의 한 가지가 읽는다
- **하지 않을 것**: KLAS 로그인·자동 가져오기, 올린 PDF·이미지 서버 저장
- **끝났다는 기준**
  - 모은 강의계획서 PDF 6개 중 5개 이상에서 날짜가 맞다
  - KLAS 화면 캡쳐 5장 중 4장 이상에서 날짜가 맞다
  - 같은 6개 중 5개 이상에서 평가 비율이 맞다
  - 구글 캘린더와 아이폰 캘린더에 일정이 들어가고, 두 사람 폰에서 알림이 울린다
  - 5MB PDF를 고르면 안내가 뜨고 오류 화면이 나오지 않는다
- **참고**: [Syllabus-to-Calendar-App](https://github.com/MahalakshmiPFW/Syllabus-to-Calendar-App) (MIT), `ics` 패키지

## 핵심 2. 오늘의 브리핑 (홈 화면)

- **무엇을**: 오늘 할 일을 한 화면에 모아 보여 주고, 지금 시작할 일 하나를 추천한다.

  - 카드: 캘린더 일정 중 오늘·이번 주 마감(D-day), 대외활동·취준 일정 (모두 함께)

- **끝났다는 기준**: 홈에서 오늘 마감이 보인다 · 내보낸 파일로 다른 폰에서 기록이 복원된다

### 2-1. 오늘의 한 가지 (시안 `01-오늘의한가지.png`)
- **무엇을**: 오늘 쓸 수 있는 시간을 고르면, 마감 전 할 일 중 **효율**이 가장 높은 일 하나와 오늘 미뤄도 되는 일을 보여 준다. AI 없이 코드로 계산한다.
- **화면 (위에서 아래로)**: 제목 '오늘의 한 가지' + 날짜·주차 / 한 줄 "시간은 한정돼 있으니, 어디에 쓸지가 곧 학점이에요." / '오늘 쓸 수 있는 시간' 직접 입력(0.5~24시간, 기본 2시간) / 포인트색 블록(오늘 가장 효율 좋은 N시간: 과목, 할 일, "배점 15% · D-3 · 약 2시간", 이유 한 줄, "N시간을 모두 써요", 안쪽에 '오늘 미루는 일') / 과목별 할 일(과목은 순위 없이 앞선 일이 먼저 나온 순서, 과목은 한 줄씩 보이고 누르면 아래에서 창(`BottomSheet`)이 올라옴. 창 안의 할 일에만 1·2·3위. D-day는 18px 굵게, 3일 안이면 포인트색. 배지 '오늘 N시간' 또는 '오늘은 미뤄요'·'효율 높음/보통/낮음', 막대, 첫 번째 일이 아닌 시간 받은 일에 '이 일로 집중 시작'. 오늘 마감인 일은 효율과 상관없이 맨 앞이고 그다음은 효율 높은 순. 시간은 앞에서부터 예상 소요시간만큼 나누고, 모자라면 남은 시간만큼만 넣는다) / '목표 점수까지 몇 점 필요한지 보기 >'(⑥으로) / 계산식 각주
- **계산**: 효율 = 배점(%) × (목표 득점률 − 예상 득점률) ÷ 예상 소요시간, 마감 3일 안이면 ×1.3, 7일 안이면 ×1.15
  - 배점: `unis.grading.v1`의 그 종류 비율 ÷ 같은 과목·같은 종류 일정 수. 평가 비율이 없으면 기본값(중간·기말 30, 과제 10, 퀴즈 5)
  - 예상 득점률: 시험 대비 팩 퀴즈 정답률이 있으면 그 값, 없으면 0.6. 목표 득점률은 ⑥에서 정한 목표 ÷ 100, 없으면 0.9
  - 예상 소요시간: 기본값(중간·기말 8시간, 과제 3시간, 퀴즈 1시간, 기타 1시간), 일정마다 고칠 수 있음
- **'시작' 버튼**: 추천 일을 누르면 ⑤ 집중 모드가 그 과목·일정으로 시작된다
- **할 일 직접 넣기**: 강의계획서에 없는 과제·퀴즈를 직접 넣고 고친다. 들어가는 곳은 이 화면의 '할 일 넣기'와 홈 메뉴의 '할 일 직접 넣기'. 칸은 과목·이름·종류·마감일(필수), 시작일·예상 시간·내용(선택). `unis.deadlines.v1`에 `startDate`, `hours`, `memo`로 저장해 백업에도 들어간다. 시작일이 아직 안 된 일은 순위에서 빼고 '아직 시작 전'에 보여 준다. 예상 시간이 있으면 효율과 시간 분배에 그 값을 쓴다. 내용은 AI에 보내지 않는다
- **끝났다는 기준**: 예시 일정 5개로 손으로 계산한 순서와 같다 · 시간을 바꾸면 추천이 바뀐다

## 핵심 6. 기말 필요 점수 (시안 `02-최소점수계산.png`)
- **누가·언제**: 기말 2~3주 전, "기말을 몇 점 받아야 하지?"가 궁금할 때
- **무엇을**: 과목을 고르고 목표 총점을 정하면, 지금까지 받은 점수로 **기말 필요 점수**를 거꾸로 계산한다. AI 없음.
- **화면 (위에서 아래로)**: 뒤로 '< 오늘의 한 가지' / 제목 '최소 점수 계산' + "최소 이 점수만 넘기면 돼요. 목표를 정하면 기말 필요 점수를 거꾸로 계산해요." / 과목 칩 / 목표 총점 블록(숫자, 슬라이더, 칩 A+ 95 · A0 90 · B+ 85 · B0 80, "학점 컷은 교수님마다 달라서, 내가 정한 기준 점수예요.") / 포인트색 블록("경영통계 · 목표 85점이면, 기말에서 최소" 큰 숫자 **83.3점**, "기말 배점 30점 중 25점이 필요해요.", 상태 배지) / '기말 100점 만점 기준, 필요한 점수의 위치' 막대(여유 0~70 · 주의 70~85 · 위험 85~100) / '지금까지 확보한 점수'(항목별 받은 점수/배점 막대, 기말 전까지 확보 합계, 기말 배점) / '과목별 방어선'(과목마다 기말 최소 점수 + 배지) / '부담이 몰리는 주 보기 >'(⑦로) / 계산식 각주
- **입력**: 평가 항목과 배점은 `unis.grading.v1`(① 저장)에서 읽고, 없으면 직접 입력. 항목별 받은 점수를 입력 (모르는 항목은 비워 두면 계산에서 빼고 안내)
- **계산**: 필요 점수 = (목표 총점 − 기말 전까지 확보한 점수) ÷ 기말 배점 × 100
  - 목표 총점은 100점 기준이다. 배점 합이 100이 아니면 목표 점수 = 배점 합 × 목표 ÷ 100으로 바꾸고 안내한다 (합 120, 목표 85 → 102)
  - 받은 점수는 받은 대로 넣는다: 점수와 만점을 넣으면 배점 기준으로 바꾼다 (80 / 100, 배점 30 → 24)
  - **상대평가 추정(기본)**: 교수님이 알려 준 평균을 넣으면 학점별 예상 컷과 기말 필요 점수를 한 번에 보여 준다. 예상 컷 = 전체 평균 + z × 퍼진 정도(표준편차). 평균을 모르는 항목은 내 점수로, 기말 평균은 입력한 평균의 비율로 본다. 기본값(퍼진 정도 10, A+ 상위 15%·A0 30%·B+ 50%·B0 70%)은 임시 값이고 사용자가 고칠 수 있다. 화면에 '추정'이라고 표시한다. 절대평가로 바꾸면 슬라이더로 목표를 직접 정한다
  - 상태: 100 초과 **목표 초과**(검정, 기말 만점일 때의 총점과 "상대평가면 실제 컷은 더 낮을 수 있음"을 함께 안내) / 85 이상 **위험**(분홍) / 70 이상 **주의**(주황) / 그 아래 **여유**(초록)
- **저장**: `unis.grades.v1` = `{ [과목]: { target, scores: { [항목]: 받은 점수 }, averages?, mode?, grade?, estimate? } }`, 백업 포함. target은 상대평가에서 고른 학점의 예상 컷으로 맞춘다
- **안내 (각주)**: "상대평가 과목은 실제 컷에 따라 달라질 수 있어요."
- **끝났다는 기준**: 예시 3과목의 필요 점수와 상태가 손 계산과 같다 · 평가 비율이 없는 과목도 직접 입력으로 계산된다

## 핵심 7. 학기 리스크 지도 (시안 `03-학기리스크지도.png`, 2026-11-04 읽기 쉽게 변경)

  - 예상 공부 시간: 할 일에 직접 넣은 값, 없으면 시험 8시간, 과제 3시간, 퀴즈·기타 1시간 (2-1과 같음). 전에 쓰던 '시간 × 난이도' 점수는 이해하기 어려워서 없앴다
  - 마감 주에 몰아서: 시험 공부를 모두 시험 주에 둔다고 가정. 미리 나눠서: 시험 공부의 70%를 시험 4주 전부터 나눠 배치
  - 몰린 주 = 남은 주 평균의 1.5배 이상. 1주차 = 개강일(2026-09-01)이 속한 주
- **끝났다는 기준**: 예시 일정으로 칸 숫자·합계·몰린 주가 손 계산과 같다 · '미리 나눠서'에서 몰린 주의 합계가 줄어든다

  - AI(`web/src/app/api/receipt`): `{situation, task, action, result, oneLiner(80자 이내), competencies: 1~3개}` → `zod` 검사. **입력에 없는 숫자·사실은 만들지 않는다**, 숫자가 없으면 `[숫자를 넣으면 더 좋아요]`만
  - 역량은 아래 표의 역량 이름에서만 고른다. 확인·수정 후 저장 `unis.receipts.v1`, 백업 포함
- **역량 공백 지도 (시안 그대로)**: 제목 + "스펙 영수증 N장 · 활동 N개 기준" / '목표 직무' 칩 / 요약 블록("마케팅 기획에 필요한 역량 8개 중 4개를 채웠어요", 칸 막대, 채움·보강 필요·비어 있음 개수) / '역량별 상태' 2열 칸(채움=포인트 테두리, 보강 필요=주황 테두리, 비어 있음=점선 테두리, 점 3개, "영수증 N장 · N시간") / '먼저 채울 칸'(비어 있는 칸부터 최대 4개, 무엇을 기록하면 되는지 한 줄) / '내 활동 기록'(활동별 집중 시간·자소서 재료 수·역량, 영수증이 없으면 '기록 없는 시간' 배지 + 'STAR로 기록하기') / 계산식 각주
  - 상태: 그 역량 영수증 2장 이상 **채움**, 1장 **보강 필요**, 0장 **비어 있음**
  - 시간: ⑤ 집중 모드에서 그 활동으로 기록한 시간 합계. 같은 활동은 한 번만 더한다
  - 고른 목표 직무는 `unis.targetJob.v1`에 기억하고 파일·계정 백업의 선택 항목 `targetJob`에 포함한다. 옛 백업도 읽고, 가져올 기기에 이미 고른 직무가 있으면 유지한다 (2026-11-04 사용자 요청으로 역량 공백 지도를 먼저 만듦)
  - 직무별 필요 역량 표 (**임시**. 이 표로 먼저 만들고, 내용은 '나중에 할 일'에서 팀이 채웁니다. 표는 `web/src/lib/competencies.ts` 한 곳에만 두어 나중에 그 파일만 고치면 되게 합니다):

    | 목표 직무 | 필요 역량 8개 (임시) |
    |---|---|
    | 마케팅 기획 | 시장 분석, 기획력, 콘텐츠 제작, 데이터 분석, 발표·설득, 협업, 문제 정의, 커뮤니케이션 |
    | 데이터 분석 | 데이터 분석, 통계, 도구 활용(SQL·엑셀), 문제 정의, 시각화, 발표·설득, 협업, 커뮤니케이션 |
    | 서비스 기획 | 문제 정의, 기획력, 사용자 조사, 데이터 분석, 문서 작성, 발표·설득, 협업, 커뮤니케이션 |
    | 재무·회계 | 회계 지식, 재무 분석, 도구 활용(엑셀), 정확성, 문서 작성, 문제 정의, 협업, 커뮤니케이션 |

- **끝났다는 기준**: 실제 경험 5개로 영수증 5장, 5장 모두 입력에 없는 숫자·사실이 없다 · 공백 지도 상태가 영수증 수와 맞다 · 내보낸 파일로 다른 폰에서 영수증이 복원된다

## 제외
- **KLAS 직접 연동**: 공식 API가 없고 비공식 연동은 보안·약관 문제. 대신 KLAS 화면을 캡쳐해 올리면 AI가 인식한다
- **공고 사이트 자동 가져오기**: 사이트마다 약관·차단 문제. 캡쳐나 글 붙여 넣기로만 받는다
- **Supabase·참가 코드**: 쓰지 않는다. 사용 기록은 시범 기간 익명 통계(⑭)만, 시범 운영 뒤에는 모으지 않는다

## 모든 기능 공통
- **개인정보**: 개인 데이터(일정·점수·대외활동·영수증·집중 기록)는 폰(브라우저)에만. 서버에는 저장하지 않고, AI에는 사용자가 입력한 글·이미지만 잠깐 보냄. 새 저장 키는 내보내기·가져오기에도 넣음
- **저작권**: 올린 강의자료는 저장·공유하지 않음, 화면에 안내 문구
- **AI 오류**: 날짜·평가 비율은 사용자 확인 후 저장, 퀴즈는 해설과 함께, 영수증은 입력에 없는 사실을 만들지 않음
- **계산 화면**: 숫자가 나오는 화면(2-1·⑥·⑦·⑩)은 맨 아래에 계산식 각주. 예시 데이터일 때는 '예시 데이터' 표시
- **비용·남용**: 콘솔 월 사용 한도, 하루 20회 제한(모든 AI 기능 합쳐서, 로그인 사용자는 계정별·안 한 사용자는 기기별), 입력·답변 길이 상한, 빠른 모델 기본
- **PDF·이미지 크기**: 4MB 넘으면 안내 (Vercel 4.5MB, Claude PDF 32MB·100쪽, 이미지 1장 5MB)
