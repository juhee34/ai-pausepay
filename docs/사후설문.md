# 팀 메모 (참가자에게 주지 않음)

## 질문과 분석 연결

| 알아낼 것 | 질문 | 분석 |
|---|---|---|
| 발표에 써도 되는지 | 동의 | '아니요'는 빼고, '통계로만'인 사람의 5번 글은 인용하지 않기 |
| 문제가 실제로 있는지 | 1 | '그렇다' 이상 비율 = 학업 정리 필요성 (발표의 문제 검증) |
| 쓰기 편했는지 | 2 | '편리했다' 이상 비율, 만족도 대신 사용 |
| 가장 좋았던 기능 | 3 | 기능별 순위, 발표의 '가장 도움 된 기능' |
| 다음에 만들 기능 | 4 | 순위와 '기타' 글, 발표의 '다음 단계' 근거 |
| 칭찬과 개선점 | 5 | 짧은 의견 정리, 동의한 답만 인용 |

## 분석할 때 주의
- **표본이 작아요 (15~30명).** 결과는 "경향"으로만 말해요.
- **동의를 먼저 걸러요.** '아니요' 응답은 빼고, 의견 인용은 '네, 사용해도 됩니다'를 고른 답에서만 골라요.

## 11/10 줄이면서 뺀 것
설문을 1분 안에 끝내려고 뺐어요. 필요하면 **인터뷰 3명**에게 묻는 것으로 대신해요.
- **'실제 걸린 시간'** (A가 예상 소요시간 기본값을 고치려고 요청한 문항): 인터뷰 질문으로 옮겨야 해요.
- **추천 의향(NPS), 다음 학기 사용 의향, 지불 의향:** 발표의 결과·비용 슬라이드는 이 숫자 대신 2번(편리함)과 인터뷰로 채워요.
- **가설 3개** (시험 준비 시작 시점, 리스크 지도 보고 앞당겼는지, 자소서 막막함): 인터뷰로 확인해요.
- **학년, 전공 계열, 사용 일수, 원래 쓰던 도구, 강의계획서 정확도**
