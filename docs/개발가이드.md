### 완료 체크의 의미

로드맵의 초기 체크는 코드와 병합 기록으로 확인한 구현 완료입니다. 실제 폰 통과를 뜻하지 않습니다. 폰 검증표는 아직 미확인이므로 검증 항목은 비워 두었습니다. 팀이 체크를 바꿔도 확인 기준일과 Git 근거는 그대로 남습니다.

### 문서가 다르면

기능 범위·완료 기준·일정은 docs/PRD.md를 따릅니다. 계정은 11/4 멘토 결정과 AGENTS.md가 우선입니다. 담당자는 docs/역할분담.md, 시각 규칙은 docs/DESIGN.md를 봅니다. 이 웹앱은 그 내용을 보기 쉽게 정리한 11/4 스냅샷입니다.

### Git에서 새로 확인한 것

#63·#65는 이미 main에 병합되어 오늘 할 일 순위·직접 입력을 구현 완료로 표시했습니다. #68·#70에는 계정 진단과 Webpack 빌드 변경이 들어 있습니다. feature/exam-short의 단답형은 아직 main에 없으므로 배포 완료로 표시하지 않습니다.

## 처음 실행하는 방법

명령은 한 줄씩 실행합니다. 키 값은 채팅이나 코드에 쓰지 않습니다.

### 1 · web 폴더로 이동

cd web
실제 웹앱 코드가 있는 폴더로 이동합니다.

### 2 · 필요한 도구 설치

npm install
처음 실행하거나 package.json이 바뀌었을 때 필요한 패키지를 받습니다. 이미 설치되어 있고 바뀐 것이 없으면 생략합니다. Node.js는 package.json 기준 22.x입니다.

### 3 · 개발 서버 켜기

npm run dev
컴퓨터에서 확인용 웹앱을 켭니다. 터미널에 표시된 주소의 /team/index.html을 열면 이 문서가 나옵니다. 예: http://localhost:3000/team/index.html. 종료는 Ctrl+C입니다.

### 4 · 실제 폰 확인

배포 후 Vercel 주소 뒤에 /team/index.html을 붙여 Safari·Chrome에서 엽니다. 로컬 localhost는 폰에서 열리지 않습니다. 본 서비스는 375px 폭, 파일 업로드, .ics, 로그인·백업을 두 폰에서 확인해야 완료입니다.

### 준비 → 계획 → 구현

PRD 완료 기준 읽기 → docs/design-ref 시안 열기 → 예시 자료 준비 → 변경 계획 확인 → 계산 함수 또는 AI 없는 화면 구현 → 필요한 기능에만 서버 AI 연결.

### 검증 → 공유

손 계산·예시 입력과 비교 → 오류·빈 상태·4MB 초과 입력 확인 → 두 폰에서 확인 → 변경 파일만 커밋 → 상대방 PR 검토 → main 병합 → Vercel 배포 재확인. 실제 강의자료나 개인정보 캡쳐는 Git에 넣지 않습니다.

## 어느 파일을 열면 될까요?

### 화면 · web/src/app/

홈 page.tsx · 일정 업로드 calendar/ · 우선순위 today/ · 점수 grades/ · 리스크 risk/ · 집중 focus/ · 시험 exam/ · 메일 mail/ · 취업 career/ · 마이페이지 my/.

### 계산·저장 · web/src/lib/

today-plan.ts(순위) · grades.ts(점수) · risk.ts(부담) · skill-gap.ts(역량) · deadline-store.ts(일정) · activity-store.ts(활동) · receipt-store.ts(영수증) · backup.ts(파일 백업) · account-backup.ts(계정 백업).

### AI · web/src/app/api/

syllabus · briefing · timetable · exam · mail · posting · receipt. 새 AI 경로는 lib/ai-route.ts 공용 도우미를 씁니다. 현재 코드의 연결 파일은 lib/claude.ts의 getAnthropic()이며 @anthropic-ai/sdk를 사용합니다. Codex 도구 사용과 웹앱 API 과금은 별개입니다.

### 계정 · Firebase

firebase.ts·firebase-auth.ts는 화면 로그인, firebase-admin.ts는 서버 확인, firestore.rules는 접근 규칙입니다. 사용자는 자기 uid 문서만 읽고 쓰며, 사용량은 서버만 기록합니다. calendar-subscription.ts는 비밀 ICS 주소와 백업 일정 읽기를 담당합니다.

### 이 문서 웹앱

web/public/team/content.js가 내용의 원본입니다. app.js는 화면·체크 동작, style.css는 디자인입니다. 내용 변경 후 저장소 루트에서 node scripts/build-handbook.mjs를 실행하면 docs/소개서.md·개발가이드.md가 같은 내용으로 갱신됩니다. 새 패키지는 필요 없습니다.

## 꼭 지킬 개발 규칙

### AI가 판단할 것과 계산할 것

AI는 사용자가 준 글·PDF·이미지만 읽고 서버 API에서 호출합니다. 오늘의 한 가지·기말 점수·리스크·공백 지도는 AI 없이 lib 함수로 계산하고 화면 아래 계산식을 적습니다. 영수증에 없는 숫자나 사실을 만들지 않습니다.

### 입력과 비용 보호

업로드 전에 4MB 제한을 확인합니다. 큰 시험 자료는 지원되는 쪽 범위 선택을 이용합니다. ai-route.ts의 하루 횟수·시간 제한·오류 처리와 입력·출력 상한을 유지합니다. 로그인은 계정별, 비로그인은 기기 쿠키별 제한이며 별도로 API 비용 한도를 확인합니다.

### 저장과 백업

학생 데이터는 기본 localStorage(현재 브라우저에 남는 저장소)입니다. 새 학생 데이터 키는 backup.ts의 내보내기·가져오기와 계정 백업 검사에 함께 넣습니다. 원본 자료와 AI에 보낸 글은 서버에 저장하지 않습니다. 계정 백업은 정리된 결과만 올립니다.

### 키와 Git

web/.env.local은 커밋하지 않습니다. main에 직접 커밋하지 않고 feature/기능이름 → PR로 합칩니다. git push --force와 git add .는 쓰지 않습니다. feat:·fix:·style:·docs:로 커밋 목적을 적습니다. 패키지를 추가하기 전에 이유를 공유합니다.

### 디자인

버건디 포인트, 밝은 회색 바탕, 둥근 흰 카드, 44px 이상 터치 영역을 씁니다. 실제 앱은 375px 우선·최대 폭 480px, 문서 웹앱은 PC에서 넓은 목차형 레이아웃입니다. 새 분석 화면은 docs/design-ref의 해당 시안을 먼저 엽니다.

### 학교·취업 준비

### 로그인·사용량·백업

아이폰·안드로이드에서 로그인·로그아웃하고 비로그인 이용도 확인합니다. 로그인 AI 503이 해결됐는지 실제 요청으로 봅니다. 같은 계정의 사용량이 두 폰에서 같고, 다른 폰에서 계정 백업을 받으면 같은 일정이 나오는지 확인합니다. 다른 계정의 문서 접근은 거절되어야 합니다.

### 캘린더 구독

구글·아이폰 캘린더에서 비밀 ICS 주소를 구독합니다. 우니스 일정 수정 → 계정 재백업 → 외부 캘린더 갱신을 확인합니다. 주소 교체 후 옛 주소가 거절되는지도 봅니다. 주소 원문이나 개인정보를 검증 메모에 적지 않습니다.

### 배포에서만 생기는 문제

npm run build는 배포용 파일을 만드는 확인 명령입니다. 현재 dev·build는 Webpack을 사용합니다. 환경 변수 변경은 Vercel에서 재배포까지 해야 적용됩니다. 코드가 병합되었다고 로그인·AI가 배포에서 정상이라는 뜻은 아닙니다.

## 체크리스트를 함께 쓰는 방법

### 저장 범위

개발 순서에서 체크하면 이 브라우저에만 저장됩니다. 팀 문서의 체크 기록은 학생 계정 백업과 별개이며 자동으로 팀원과 동기화되지 않습니다. 저장을 사용할 수 없으면 안내가 나오고 현재 화면에서만 바꿀 수 있습니다.

### 내보내기·가져오기

체크 기록 내보내기로 JSON 파일을 받아 팀원에게 전달합니다. 가져오기는 파일의 체크 상태로 현재 체크를 교체하므로 먼저 내 기록을 내보내 두세요. 저장 실패 시 화면에서 계속 확인할 수 있고, 파일은 별도로 보관합니다. 체크 기록에 학생 자료·이메일·비밀 주소를 넣지 않습니다.

### 진도를 최신으로 바꾸기

체크는 자유롭게 수정할 수 있고 초기 Git 근거와는 분리됩니다. 새 구현·병합이 생기면 content.js의 항목·근거·기준일을 고친 뒤 문서를 다시 생성합니다. 개발 순서의 완료율은 미룬 항목을 제외한 체크 항목 기준입니다.
