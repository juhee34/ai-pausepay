# 역할 분담 (충돌 없이 같이 만들기)

2026-11-02 기준. 원칙은 **"폴더를 나눠 갖고, 같이 쓰는 파일은 주인을 한 명 정한다"**입니다. 일정은 개발가이드 2회차(11/3~11/9, 메일·브리핑)에 맞췄습니다. 담당이 바뀌면 이 문서를 먼저 고칩니다.

## 누가 무엇을

### A — 캘린더 → 오늘의 브리핑
브리핑은 캘린더에 저장한 일정을 읽어서 보여 주는 화면이라, 같은 사람이 이어서 만듭니다.

| 순서 | 기능 | 내용 |
|---|---|---|
| 1 | 하단 탭바 | 나눠 작업하기 전에 **작은 PR로 먼저** 합칩니다 |
| 2 | 캘린더 3단계 | 날짜 확인·수정, `localStorage` 저장, `.ics` 내려받기(알림 포함), 날짜 없는 일정(예: "8주차 중간고사")은 사용자가 날짜를 넣게 |
| 3 | 오늘의 브리핑 | 홈 화면: 지금 시작할 일 한 줄, 오늘·이번 주 마감, 대외활동, 데이터 내보내기·가져오기 |
| 4 | AI 사용 제한 붙이기 | B가 만든 `ai-limit.ts`를 `/api/syllabus`에 적용 |

**A의 파일**: `web/src/app/calendar/**`, `web/src/app/api/syllabus/**`, `web/src/app/page.tsx`, `web/src/lib/syllabus.ts`

### B — 교수님 메일 작성기 → 시험 대비 팩

| 순서 | 기능 | 내용 |
|---|---|---|
| 1 | 교수님 메일 작성기 | 상황 5개(성적 문의·결석 사유·추천서·면담·과제 연장), 초안, 보내기 전 체크리스트, 복사 버튼 |
| 2 | AI 사용 제한·스트리밍 공용 도구 | 기기당 하루 횟수 제한, 입력·답변 길이 상한, 답변 스트리밍. 메일 작성기에서 먼저 만들고 다른 기능이 재사용 (PRD 핵심 4) |
| 3 | 시험 대비 팩 | 5줄 요약 → 객관식·OX 10문제(해설 포함) → 채점 → 틀린 문제만 다시. 쪽 범위 선택 |

**B의 파일**: `web/src/app/mail/**`, `web/src/app/api/mail/**`, `web/src/app/exam/**`, `web/src/app/api/exam/**`, `web/src/lib/ai-limit.ts`

## 같이 쓰는 파일

| 파일 | 주인 | 규칙 |
|---|---|---|
| `web/src/app/layout.tsx`, 하단 탭바, `web/src/app/globals.css` | A | 탭바 PR이 합쳐진 뒤에는 각자 자기 화면만 만집니다 |
| `web/src/lib/ai-limit.ts` | B | 완성되면 A가 `/api/syllabus`에 붙입니다 |
| `web/src/lib/claude.ts` | 손대지 않기 | 모델 이름은 각자 자기 API 파일 안에 적습니다 |
| `web/package.json`, `web/package-lock.json` | 먼저 말한 사람 | 설치 전에 카톡으로 알리기. 충돌이 나면 직접 고치지 말고 `npm install`을 다시 실행 |
| `docs/PRD.md`, `CLAUDE.md` | 둘이 합의 | 기능 범위나 규칙이 바뀔 때만 고칩니다 |
| PAUSEPAY 시절 파일 (`risk-score` 등) | 둘이 합의 | 합의하기 전까지 그대로 둡니다 |

## 매일 지킬 습관

1. 일을 시작할 때마다 최신 `main`을 받고 새 브랜치를 만듭니다.
   ```bash
   git switch main
   git pull
   git switch -c feature/기능이름
   ```
2. PR은 작게, 기능 단계마다 하나씩. **상대방이 확인하고** 합칩니다.
3. 남의 폴더 파일을 고쳐야 하면 직접 고치지 말고 먼저 말합니다.
4. 각자 자기 API 키를 `web/.env.local`에 넣습니다 (같은 콘솔 계정에서 키를 따로 만들기). 키는 카톡·채팅·코드에 쓰지 않습니다.
5. 테스트에 쓴 실제 강의계획서·KLAS 캡쳐는 커밋하거나 단톡에 올리지 않습니다 (교수님 연락처 등 개인정보가 들어 있음).
